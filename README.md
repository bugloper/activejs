# activejs

A port of Rails' [ActiveSupport](https://github.com/rails/rails/tree/main/activesupport) to JavaScript. It has no dependencies and ships as ESM. It needs Node ≥ 20 (it uses `node:crypto`, `node:zlib` and `AsyncLocalStorage`).

Where it makes sense, output is checked against real ActiveSupport. `test/fixtures/rails_parity.json` is generated by running Rails 8.1, and the test suite compares against it: inflections, number helpers, ISO 8601 durations, `to_query`, HTML escaping, time zones across DST, and the `MessageVerifier`/`MessageEncryptor` wire formats.

```sh
npm install @bugloper/activejs
```

Import `core_ext` once, at your app's entry point, and call the methods on strings, arrays, numbers and dates, the way `require "active_support/core_ext"` works in Rails:

```js
import "@bugloper/activejs/core_ext";

"   ".isBlank();                         // true
"person".pluralize();                    // "people"
"active_model/errors".camelize();        // "ActiveModel::Errors"
"Once upon a time".truncate(10);         // "Once up..."
["a", "b", "c"].toSentence();            // "a, b, and c"
[{ name: "a" }, { name: "b" }].pluck("name"); // ["a", "b"]
(2).days().ago();                        // Date two days ago
(1234567).toFs("delimited");             // "1,234,567"
new Date().beginningOfMonth();
new Date().plus((1).month());
```

Classes such as `Duration`, `TimeZone`, `MessageVerifier` and `Cache` come from the main entry point:

```js
import { Time, MemoryStore, MessageVerifier } from "@bugloper/activejs";
import "@bugloper/activejs/core_ext";

Time.zone = "Eastern Time (US & Canada)";
Time.zone.local(2024, 3, 10, 1, 30).plus((1).hour()).toString();
// "2024-03-10 03:30:00 -0400"  (crosses the DST gap like Rails)
```

The added methods are non-enumerable. They never replace a method JS already has, so native `String#at` and `Array#at` keep working, and `uninstall()` removes them all. `Object.prototype` is not patched, so for plain objects, `null` and `undefined` use the functions below (`isBlank(null)`, `deepMerge(a, b)`, …).

### Without patching prototypes

Every method is also exported as a plain function that takes the value as its first argument. That suits libraries, where changing built-in prototypes would affect the people using the library:

```js
import { isBlank, toSentence, pluralize, DateExt } from "@bugloper/activejs";

isBlank("   ");                          // true
toSentence(["a", "b", "c"]);             // "a, b, and c"
DateExt.beginningOfMonth(new Date());
```

## Translating from Ruby

| Ruby | activejs |
| --- | --- |
| `blank?`, `present?`, `many?` | `isBlank`, `isPresent`, `many` |
| `options.foo!` | `options.fooBang()` |
| `2.days.ago` | `days(2).ago()` or `(2).days().ago()` |
| `throw :abort` | `abort()` |
| `Time.zone.local(2024, 1, 31)` | `Time.zone.local(2024, 1, 31)` — months are 1-based, as in Ruby |
| `date.change(month: 2)` | `change(date, { month: 2 })` — 1-based here too, although `Date#getMonth()` is 0-based |
| `date.all_month` (a Range) | `allMonth(date)` → `[start, end]` |
| `snake_case` keyword options | `camelCase` options (`keepIdSuffix`, `expiresIn`, …) |

## Deliberate differences

- **One Date type.** JS has no separate `Date`/`Time`, so `DateExt` works on `Date` in the host's local zone, the way Ruby's `Time` does without `Time.zone`. Use `TimeWithZone` for zone-aware math.
- **Message formats.** `MessageVerifier` and `MessageEncryptor` use JSON (no Marshal). By default they write the metadata envelope that Rails apps on `load_defaults 7.1`+ produce. Pass `useMessageSerializerForMetadata: false` for the legacy envelope. Both envelopes are always readable. `MessageEncryptor` defaults to `aes-256-gcm`, which is what Rails apps use; standalone ActiveSupport still defaults to CBC, so pass `cipher: "aes-256-cbc"` to read those messages.
- **`Digest`** defaults to MD5, as ActiveSupport does. Set `Digest.hashDigestClass = "sha256"` to match apps on `load_defaults 7.0`+.
- **Async.** `runCallbacksAsync`, `Notifications.instrument`, `ErrorReporter#handle`, `Cache#fetch` and the time helpers all accept async blocks.
- **Zone abbreviations** come from `Intl`, so some zones show `GMT+1` where Ruby's tzinfo says `CET`.

## Not ported

These have no meaningful JS equivalent, or they belong to Rails' runtime rather than to a utility library: `HashWithIndifferentAccess` (JS keys are already strings), `Multibyte`/`mb_chars`, `XmlMini`/`to_xml`, I18n-backed locale lookups in the number helpers, Marshal, the file/memcache/redis cache stores, Executor/Reloader, file watchers, autoloading, `EncryptedConfiguration`, and the Minitest assertion helpers (`assert_difference`, …).

## TypeScript

Type declarations ship with the package and are generated from JSDoc in the sources. Importing `@bugloper/activejs/core_ext` also adds global declarations, so `"person".pluralize()` and `(2).days()` type-check. Some members are defined at runtime and can't be typed statically, such as `CurrentAttributes.attribute(...)` accessors and `StringInquirer`'s dynamic predicates. Those resolve to `any`.

What the numbers mean:

- **Against Rails:** most operations are several times faster, mainly because V8 runs this kind of code faster than Ruby, not because of anything clever in the port.
- **Where activejs is slower:**
  - Time zone math (`TimeWithZone`) is about 5× slower than Rails. Every zone conversion goes through `Intl.DateTimeFormat#formatToParts`, and resolving a local time safely across DST takes several of those calls. If you do zone math in a hot loop, convert once and work with the results.
  - `strftime` is a little slower than Ruby's, which is implemented in C.
  - `JSON.encode` walks the value to apply Rails' `as_json` rules (dates, Maps, Sets, `asJson()` hooks, HTML-safe escaping) before stringifying, so it's slower than `JSON.stringify`.
- **The lodash columns aren't equivalent:** `camelCase`, `snakeCase`, `startCase` and `kebabCase` don't follow Rails' inflection rules (acronyms, `_id` suffixes, `::` namespaces) and don't transliterate accents the way `parameterize` does. They're included to show the cost of that extra work.

To rerun the benchmarks (Ruby, `activesupport` and `benchmark-ips` are needed for the Rails column):

```sh
cd bench && npm install && npm run bench:write   # updates the table above
```
